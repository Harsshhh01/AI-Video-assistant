    How it works

    Six stages, each visible while it runs. Nothing is uploaded anywhere except the text sent to the language model.

    1. 01

      Acquire audio

      yt-dlp pulls the best audio track from a link; uploads are read straight off disk.

    2. 02

      Normalise

      ffmpeg converts everything to 16 kHz mono WAV and slices it into chunks.

    3. 03

      Transcribe

      Whisper runs locally for English. Hinglish goes to Sarvam, which translates as it transcribes.

    4. 04

      Summarise

      Long transcripts are mapped chunk-by-chunk, then folded into one clean summary.

    5. 05

      Extract

      Action items with owners and deadlines, decisions taken, questions left open.

    6. 06

      Index & chat

      Passages are embedded into a per-analysis Chroma collection for grounded Q&A.

    Questions

    Does my recording leave my computer?

    The audio does not. English transcription runs locally through Whisper. The resulting text is sent to the Mistral API for summarisation and to answer your questions. Hinglish is the exception: that audio is sent to Sarvam AI for translation.

    Why is it slow?

    Whisper transcribes on your CPU. Set WHISPER_MODEL=base or tiny in .env for a large speed-up at some cost in accuracy, or medium when accuracy matters more than time.

    What happens to the files afterwards?

    Uploads and intermediate WAV chunks are deleted as soon as the analysis finishes. The transcript and its vector index live in memory and on disk under data/ until you delete the analysis or restart the server.

    Can I run it without the web interface?

    Yes — python -m app.cli "https://youtu.be/…" --output report.md runs the same pipeline in the terminal and drops you into a chat prompt.
